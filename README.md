# SystemDesign

Concise notes and worked examples for learning and discussing large-scale system design.

## About
This repository collects short notes, design sketches, and practical examples to help you learn system design concepts and trade-offs. Entries are focused, editable, and written for quick reading.

## Structure
Recommended layout (I will reorganize files to match this):
- designs/          — full system design examples (one system per folder)
- patterns/         — design patterns, tradeoffs, antipatterns
- case-studies/     — real-world examples and analysis
- diagrams/         — architecture diagrams and source files
- notes/            — KB files and concise topic notes
- archive/          — removed/experimental content (if any)
- README.md         — this file

## How to use
- Read `notes/` for concise topic summaries.
- Browse `designs/` for example architectures, APIs, data models, and scaling notes.
- Keep editable diagrams (drawio, svg) in `diagrams/` so they can be improved.
- Prefer short, focused READMEs per design describing constraints, architecture and tradeoffs.

## Contributing
- Create small, focused changes on feature branches (e.g., `feat/<topic>` or `chore/cleanup`).
- Use clear commit messages (e.g., `chore: add README`, `fix: remove prompt fragments`).
- If adding a new design, create a folder under `designs/` with a README, diagrams, and examples.

## Branching & PRs
- Feature branch naming: `chore/readme-cleanup`, `feat/<topic>`, `fix/<issue>`.
- Create PRs with a short summary and list of changes.
